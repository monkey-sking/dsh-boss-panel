# 会话状态模型（唯一权威定义）

> 更新 2026-10-27。改分类规则必须同步改本文件，并跑 `node test/classify_test.mjs`。

## 一、只有四类，别再堆

面板上每一行会话，落在下面**四个动作类别**之一。多一个状态就等于多处地方要维护，
历史上正是「已读不回」「未验证」「可静默」几个桶互相盖来盖去，才反复出现假待办和真漏回。

| 类别 | 含义 | 用户要做什么 |
|---|---|---|
| **要我做** | 球在我这边：对方问了话、系统要我点确认、约好了面试 | 处理（回话/点按钮/去面试） |
| **等对方** | 球在对方：我已经发了话、对方已读未回（48h 内）、对方说在处理 | 等，不催 |
| **不用管** | 结论已定：婉拒、硬门槛不符、客套收尾、我主动收尾、超时 | 什么都不用做 |
| **需核对** | 面板拿不准：数据没覆盖到，怕把真欠回复藏起来 | 打开线程看一眼（少见） |

**「等回复」= 要我做 + 等对方。**

## 二、八个状态到四个类别的映射

| 状态 | 类别 | 什么时候落进来（触发条件摘要） |
|---|---|---|
| `待回复` | 要我做 | 列表侧红色未读（owed）且末条是对方；占位符 + owed（逼 live 复核）；我方已读未回但仍在 48h 内 |
| `待你决定` | 要我做 | 系统面试邀请、对方抛来需要拍板的问题（薪资/时间/是否接受），且 **7 天内** |
| `已约面试` | 要我做 | `interview_schedule.json` / `appointments.json` 里有带**具体时间**的约面或电话/线上沟通 |
| `已面试` | 要我做 | 面试已发生，等结果 |
| `等对方` | 等对方 | 我方末条 + 对方已读但**今天/昨天**；对方说「我转给用人部门/二审/有反馈会通知」这类流程告知；客套应答 |
| `可静默` | 不用管 | 对方最后一条是推销/无关岗位/外包外派；或「待你决定」超过 7 天自动冷掉 |
| `已结束` | 不用管 | 对方婉拒、硬门槛不符（卡学历/要 k12）、客套收尾、我方主动收尾、**已读不回超过 48h** |
| `未验证` | 需核对 | 探针这轮没扫到该会话（`unverified`），可能藏着真欠回复 |

## 三、判定顺序（改代码时按这个顺序读）

```
1. HANDLED 人工结论（签名一致就直用）
2. AUDIT 公司级人工结论
3. 硬规则：婉拒 / 我方主动收尾 / 门槛 / 无关岗位 / 占位符 / 流程告知 / 客套收尾 / 系统邀请
4. jev 批处理快照（过期快照不采信）
5. 面试表（有具体时间才算「已约面试」）
6. 未验证（探针漏扫）
7. owed 红点兜底
8. 已读不回 48h 分界
9. 默认「等对方」
```

## 四、时间规则

- **已读不回 48 小时**：今天/昨天 → 等对方；**前天及更早 → 已结束**，不追。
  （BOSS 时间粒度到「昨天/前天/日期」，用 days ≥ 2 近似 48h。）
- **待你决定 7 天**：超过 7 天没有下文 → 自动降级「可静默」。
- **等对方 3–5 天**：可轻推一次；超过 5 天 → 不必再等。

## 五、这些状态不存在（别再往回加）

- `已读不回` —— 2026-10-27 并入「等对方」+「已结束」。
- 单独标记「电话面试」—— 归「已约面试」，只是 mode 不同。

| `boss_thread_history.json` | 每个会话的真实消息流（`boss_thread_history.js` 增量抓） |

| `appointments.json` | 电话/线上沟通的约定时间 |
| `boss_jev_state.json` | 批处理快照（几天一跑，只做兜底） |

| `outsourcing_blacklist.json` | 外包黑名单 |

## 七、首触审批状态机（2026-10-28）

来源：用户在面板上点按钮决定「这条草稿发不发」，agent 只执行、不再问。

```
        ┌── pending ──┬── approved ──→ sent      (发送成功/已在聊)
        │             │       └─────→ failed    (闸门挡下/找不到会话/输入框缺失)
   (收回) └─────────────┘── skipped
```

- **pending**：agent 刚写的候选，面板显示「发出这条 / 不发」。
- **approved**：用户点了通过（写 `approvedAt`）。此后 30 分钟内（`APPROVAL_TTL`，超时自动退回 pending 并标 `approval_expired`）会被 `boss_approval_runner.py` 捞走。
- **skipped**：用户主动不发，不再出现在默认排序前面。
- **sent / failed**：只有发送侧（`boss_approvals.py settle`）能写，面板只能「收回」回 pending。
- 收回语义：用户点「收回」= 把 approved/skipped/failed 退回 pending，已发出的（sent）不回退，
  避免把真实外发记录改成未外发。

三道一致性约束：
1. `draftHash` 必须仍等于当前 `draft` 的哈希——用户看过的那段文字才允许发出去。
2. 首触必须有 `jobId` 与 `jdText`（`boss_shortlist_gate.py` 硬要求）。
3. `fact_blocked` 时状态落 failed，草稿原样保留，供人工改后再放回 pending。

### 首触线程与回复闸门（2026-10-28 补充）

主动打招呼（面板审批队列，条目带 `jobId`）建立的是**空线程**：会话里还没有对方消息。
`boss_interview_guard.js` 的回复闸门原本要求「当前必须有一条对方消息」，首触会被判
`REPLY_POLICY: current recruiter message required`，导致 9 条全部失败。现在 `assertInterviewPolicy`
支持 `allowEmptyThread`，只有携带 `jobId` 的首触条目会带上它；首触的事实与档位由
`boss_fact_gate.py` / `boss_shortlist_gate.py` 负责（后者的 REVIEW 在面板审批流里降级为 `FIT_WARN`）。
