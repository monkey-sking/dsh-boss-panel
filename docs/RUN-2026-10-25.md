## 已修故障

### 1. 面板「最近聊天正文」永远空白（严重，用户直接可见）

- 根因：`boss_thread_history.js` 读 `boss_threads_view.json`，而该文件自某次手工跑
  `boss_company_meta.js` 之后**再无人写入** → 里面是过期 state，还带「已约面试 / 已面试」
  这类探针根本不产出的值 → 面板侧 10/10 目标全 `row_missing`，history 全空。
- 修复：数据源改读探针每 2 分钟落盘的 `boss_threads_all.json`；
  目标筛选改为「`owed=true` 一律收 + 探针判不了但值得留正文的状态」；
  取最近 **12** 条（原 6 条）；定位方式换成已验证的**单趟滚动 + 可见行命中即点**
  （原「每目标各自 `scrollIntoView`、失败回顶重来」命中率≈0）。
- 实测：几乎全中，仅个别已不在列表的目标读不到。

### 2. `boss_company_meta.js` 同一死源

- 同样读 `view.json` → 抓不到公司元信息。已改为读 `boss_threads_all.json`，语法校验通过。

### 3. 面板挂着假待办（用户会以为有活没干）

- `OVR` 人工覆盖把某几家公司硬钉在「待你决定」，但实际**末条是我方且已送达/已读**，球在对方。
- 修复：`classify()` 增加 SELFTAIL 判定——覆盖值为「待你决定」而
  `lastFrom==='我' && delivery!==''` 时降级为「等对方」；
  同时把这几家的覆盖值本身改对，并把个别群发模板 + 岗前培训的公司标为「可静默」。
- 实测：「待你决定」清零，「待回复」清零。
